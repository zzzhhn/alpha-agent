# 可直接交给工作电脑 Agent 的 Prompt

你接手我的 Alpha Agent 项目，GitHub 仓库为 `zzzhhn/alpha-agent`。

请先读取当前仓库的 `docs/handoffs/2026-11-11-work-computer-roadmap.md`，并核验当前 main、打开的 PR、实际代码与线上状态。该文档完整包含我对侧栏和“今日推荐”的反馈、建议实施方向、交易方法论 P0，以及协作与验收边界。不要加载完整旧会话。

请按以下顺序推进：

1. 建立责任边界与 feature 分支，给我简短的现状和第一批实施计划。保护现有未提交工作，避免与其它电脑重复修改。
2. 落地侧栏双语命名、真实状态提示、折叠，以及今日推荐的定义说明、信息层级、时区、0–100 排名分、维度评级说明与 ticker 返回按钮。后端和 API 契约要跟上。以现有页面和组件精修，不另起炉灶。
3. 并行开展交易方法论 P0 的证据审计与基线设计，验证含成本、基准、时点一致性和样本外表现。我的目标是最终有赚钱能力，不是刷漂亮命中率或强制交易。策略参数改动先给证据和影响，不暗改现有机器人运行账户。
4. 再基于实际瓶颈优化其它模块、数据查询、存储、连接池和前后端架构，按小切片实施，避免无边界重构。

默认我使用中文、深色、桌面端。设计优先 integrate-design；没有安装则使用仓库中的移植设计约束，不擅自切换 ui-ux-pro-max。给我同页面前后对比，点开受影响的下拉、抽屉、最长列表和组合展开状态，检查相邻区域、页底及空白，不用静态测试冒充视觉验收。

保留现有 BYOK、人类和机器人账户、持仓与账本。不增加模型重试，不放宽旧价交易门槛，不为验证强制交易。不得从另一台电脑复制凭据或生产数据。新的付费服务、扩容、删除生产数据、权限/密钥变更和真实资金操作必须另行确认。

你可拆分独立 agent 任务，主 agent 统一架构、契约和验收；Sol 使用 GPT-6.1 Sol + high，Luna 如用则 max。明确每个 agent 的输入、责任文件、交付物、验证和停止条件，不让多人并行改共享文件。

每个功能用独立 `codex/` 分支和 PR，验证通过后可以合并部署，并确认真实域名上的受影响路径。过程中及时同步具体进展和 diff。未验证、无权限或证据不足的地方直说，不宣称一定赚钱。
