# Alpha Agent：工作电脑接续开发方案

日期：2026-11-11。用户默认使用中文、深色、桌面端。本文件是任务交接，不代表下列 UI 已实现或用户已验收。

## 1. 目标与边界

把 Alpha Agent 做成能够验证交易决策经济价值的个人研究与模拟交易平台。不能用更好看的分数、更多交易或漂亮回测代替可复验的赚钱证据。

- 项目：`zzzhhn/alpha-agent`；线上前端 `https://alpha.bobbyzhong.com`；后端 `https://alpha-api.bobbyzhong.com`。
- 技术：FastAPI/Python 后端、Next.js/React/TypeScript 前端、Neon PostgreSQL、Vercel 前后端部署、GitHub Actions 任务载体。以当前仓库配置为准，不按旧 README 的市场描述推断当前范围。
- 保留：现有用户、BYOK、机器人和人类账户、持仓及账本、设计系统、中文深色桌面风格。仅做模拟交易，不接入真实资金。
- 不做：另起视觉框架、全面重构、换模型、增加 LLM 重试、放宽旧价交易门槛、强制交易、扩大数据库套餐或引入付费服务。
- 本机本批负责两个机器人修复：GitHub 迟到的来源与窗口诊断；模型输入中的历史排名摘要污染。工作电脑从包含本文件的最新 `main` 开始，先接手下面的导航和推荐任务，不重复这批修改。

## 2. 跨电脑协作

1. 新电脑 clone 本仓库；已有 clone 先检查 `git status`、当前分支、未推送提交和打开的 PR，再 `git fetch origin`。不要强制重置已有工作。
2. 每个独立任务使用 `codex/` feature 分支和 PR。建议第一批为 `codex/nav-status-collapse`、`codex/picks-decision-hierarchy`、`codex/quant-evidence-baseline`，按依赖合并，不能在 main 混放未提交产物。
3. 开工在 PR 描述声明责任文件和验收范围。`Sidebar.tsx`、`i18n.ts`、共享 API 类型、设计 token、数据库迁移由一个整合者协调；其它 agent 不并行覆盖这些文件。
4. 共享的是 GitHub 的提交、PR、文档和已脱敏截图，不是本机绝对路径、完整会话、`.env`、cookie、BYOK 密钥或生产数据库导出。现有凭据不复制到工作电脑；无生产权限时先完成脱敏本地验证并明确边界。
5. 若工作电脑受公司数据政策约束，遵守其允许的项目和工具范围，不把个人生产数据同步到公司系统。
6. 可用 agent teams 分工做量化证据、前端交互和后端性能；主 agent 负责接口、私密数据、合并与生产验收。Sol 子 agent 用 `gpt-6.1-sol`、`high`，Luna 如使用则 `max`，任务必须有具体输入、输出、责任边界、验证和停止条件。小而耦合的修改由主 agent 完成。
7. 继承用户对这些需求的实施、验证后合并部署授权；真实交易、账户资金操作、删除生产数据、付费扩容、新权限及密钥变更仍需另行确认。不能把“全面优化”当作无限制变更许可。

## 4. 首批 UI 任务：完整保留用户反馈

中文模式中文在前、英文在后；英文模式英文在前、中文在后。不能靠硬拼现有混合翻译造成重复。建议拆为 `zhLabel`、`enLabel`，保留路由不变。

| --- | --- | --- |
| `/picks` | 今日推荐 | Picks |
| `/paper` | 模拟仓 | Paper Trading |
| `/alerts` | 警报 | Alerts |
| `/alpha` | 因子 | Alpha |
| `/backtest` | 回测 | Backtest |
| `/screener` | 选股 | Screener |
| `/report` | 报告 | Report |
| `/factors` | 因子库 | Zoo |
| `/evolution` | 演化监控 | Evolution |
| `/brain` | BRAIN 挖矿 | BRAIN Mining |

责任入口：`frontend/src/components/layout/Sidebar.tsx`、`frontend/src/lib/i18n.ts`、布局容器。

### NAV-2：有依据的侧栏状态提示

- 今日推荐：按实际研究快照、市场交易日与预期更新时间判断过期，不能单用 UTC 跨日或周末“超过 24 小时”判断故障。
- 警报：显示真正待处理的高优先级数量或积压状态，不把全部历史条数当警报。计数有上限显示，但完整数量可查看。
- 演化监控：区别主动关闭、未配置、正常空闲、未到计划时间、计划未到达、失败和状态未知。主动关闭不是故障。
- 其它 tabs 仅在存在明确状态契约且能引导下一步时加入提示，不要求每个 tab 都有徽章。
- 图标加简短 tooltip/键盘焦点说明，点击后定位相关状态；不只依赖颜色。加载失败显示未知，不伪装绿色。
- 复用现有健康数据或一个小型聚合接口、共享缓存和可见页低频读取。禁止每个侧栏项独立轮询、全表 count 或调用 LLM。记录数据时间，用户私有警报必须鉴权。

入口：`SystemHealth.tsx`、`frontend/src/lib/service-health.ts`、`evolution-health.ts` 以及对应后端状态接口。优先复用，必要时补聚合契约与索引。

### NAV-3：可折叠侧栏

桌面提供明确折叠按钮；折叠为紧凑导航轨道，保留选中态、异常提示和可访问名称，悬停/键盘焦点可见完整双语名称。状态在本浏览器持久化，避免 hydration 闪动。展开/收起不重置页面筛选、分页或滚动位置，不造成内容横向溢出。只用短淡入/颜色过渡，不引入用户不喜欢的分页位移动画。

### PICKS-1：解释“评级变化”

在该标题附近使用简短说明或信息按钮：同一股票在当前与上一份可比推荐快照之间，BUY/OW/HOLD/UW/SELL 等推荐档位发生变化。明确不是 A–F 维度评级，也不是实际涨跌、盈利或交易指令。显示两份快照的日期/范围；上期缺失则不伪造变化。

入口：`PicksBrowser.tsx` 的 changes、`alpha_agent/api/routes/picks.py`。

### PICKS-2：重排投资计划、理由／复查和策略跟随验证

用户现有问题：三块占据视觉中心但用途/上手方式不明；计划与理由割裂；标题和右侧按钮距离过大、按钮格式和宽度不一致；三块相同展开模式导致认知负担。

建议实施方向：

1. 主页面先回答“数据是否可用、哪些推荐变了、候选是什么”；候选列表不再被三个辅助模块挤到首屏下方。
2. 将“我的投资计划”和“投资理由与复查记录”组织为一个次级“研究记录”入口，内部区分全局投资约束与逐笔研究记录。共享入口不等于将不同数据模型合并或删除历史。
3. 全局计划用于期限、风险和持仓约束；逐笔记录用于买入/不买理由、失效条件、计划复查日和事后结果。首次进入用一个清楚的开始操作，非说明书式大段 onboarding。
4. 用户未写记录不影响浏览推荐，也不因此自动启用机器人。由 ticker 或模拟操作携带股票、快照、策略上下文进入记录，减少重复输入。
5. “策略跟随验证”保留独立、较低视觉权重的可点击收益摘要，回答固定规则跟随推荐在含成本及基准下的结果；不能混入用户个人或机器人账户收益。无有效收益时显示缺失原因与恢复入口，不能伪装 0%。
6. 不强求三个模块使用同一交互。研究记录可用现有抽屉/页内次级区域，验证曲线按需展开。标题、摘要和动作在同一紧凑容器内，用共享按钮尺寸和对齐规则；不要为了填白扩大卡片或加无关文案。

入口：`InvestmentProfile.tsx`、`InvestmentNotebook.tsx`、`InvestmentEvidence.tsx`、`RecommendationPerformance.tsx`、`PicksBrowser.tsx`。先画现有页面的信息层级前后对照，再落到现有组件中。

### PICKS-3：时区选择

使用共享时间格式化：至少“本地／北京时间”“纽约交易所时间”“UTC”；默认采用用户本地时区并明确标签。保存偏好，不改数据库 UTC 时间、交易日或任务时钟。纽约使用 `America/New_York` 处理 DST，不能固定 UTC-5。日期边界和交易所 session 日期分开。替换 `PicksBrowser.tsx` 当前手拼 `UTC` 的显示。

### PICKS-4：0–100 整数排名分

建议定义为“同一研究快照、同一可比股票池内的横截面百分位分”，而不是胜率、置信度或预期收益。

- 按完整 eligible/in-universe 有效 `composite_z` 集合计算，不按屏幕前 50、分页、搜索结果或方向过滤后的子集重算。
- 使用升序平均秩处理并列：`round(100 * (average_rank - 1) / (n - 1))`；清楚约定半数舍入方法。高分表示信号更偏多，做空榜可以显示低分并解释方向，不暗中反转评分。
- `n<2` 或缺失分值返回未知，不能补 0；保留原始 z-score、样本数、快照和方法版本用于追溯。
- 后端在快照构建或有界缓存层计算，前端只显示；与原始排序保持一致。不要仅为了新 UI 改动原融合权重、交易信号或回测策略。
- 历史快照不覆盖原数值，变更口径版本化。可以在详情中折叠显示原 z-score。

### PICKS-5：解释 A–F 维度评级

在维度评级表头提供短图例/可点击说明，键盘同样能打开；每个评级可看到维度名、真实分值/阈值及缺失原因。不是巨长 tooltip，也不是每行重复说明。

当前源代码 `alpha_agent/fusion/grades.py`：对同股票池内可用信号聚合后再次标准化；A+ ≥1.5，A ≥1.0，B ≥0.5，C+ ≥0，C ≥−0.5，D ≥−1.0，F <−1.0。并非简单 A 到 F 等距学业打分。样本不足、没有有效信号或截面无差异时为缺失，不等于 C 或 0。

阈值与算法以当前后端为唯一来源，不能在新前端再硬编码一份会漂移的规则。同步 `GradeStrip.tsx`、ticker 雷达图和接口定义，但不把弱/空维度从用户视野中无说明移除。

### PICKS-6：股票详情返回按钮

`frontend/src/components/stock/StockCardLayout.tsx`：提高“返回今日推荐”的可发现性，与左侧“信号一致度”处在同一布局基线/高度。使用已有 secondary 控件，不制造第二个主操作。返回时恢复原方向、搜索、分页和滚动位置；从直接链接进入时应有合理默认返回目标。

## 5. P0：交易方法论与经济价值验证

先建立可证伪的结果链路，再调策略。首批交付是现状审计、冻结基线和可复算的连续模拟收益，不是收益承诺。

1. 明确目标市场、可交易股票池、投资期限、持仓上限、换手约束和风险预算。已有机器人参数保持不变；提出改动须列理由和预期影响，不暗改运行账户。
2. 审计时点一致性：信号发布时间、可用数据时间、推荐快照、可执行报价、订单接受和下一根 bar 撮合。检查未来函数、复权与原始价混用、公司行动、退市/代码复用、生存者偏差、缺价和跨日补跑。
3. 在相同起止日比较固定规则推荐组合、机器人、SPY、现金及简单等权基线。包含费用、滑点、现金与持仓约束；只报一致样本期的相对收益。交易能力不等于盈利能力。
4. 连续净值、基准收益、超额收益、最大回撤、波动、换手、成本拖累、暴露/集中度、数据覆盖和样本长度一并报告。命中率是辅助指标，不是核心赚钱 KPI。
5. 对 1/3/5/20 日等持有期或阈值实验，预先确定训练、验证和最终样本外区间，按时间滚动；处理重叠收益、序列相关及多重尝试。不能反复挑选表现最好的窗口然后宣传为预测能力。
6. 单独分解数据缺失、技术失败、风控拒绝、模型选择不交易、信号确实无效。不得为了提高展示指标排除亏损样本或将缺失当作命中。
7. LLM 用于生成假设与结构化判断，不能把其摘要当市场事实、已完成交易或统计结论。排名分的差值与 bps 交易成本量纲不同，不能直接比较来断言可覆盖成本。
8. 选择 1–2 个可解释、成本可控的基线方案，与当前策略作增量对比。调研优先原始论文、官方文档和可复现开源实现，记录数据需求、适用边界及个人项目成本。不要先引入大模型群、多数据库或重训练服务。
9. 给出 Go / No-go / Evidence insufficient，而不是必须得出“能赚钱”。样本不足则说明需要多少后续自然观察与为何需要；不人为增加交易充样本。

入口：`alpha_agent/api/performance.py`、`backtest/tier_validation.py`、`paper/bot_analytics.py`、`paper/bot_execution.py`、`paper/intraday.py`、`storage/product_ledger.py`，以及上述研究/验证文档。

## 6. 其它模块与后端架构

在 P0 证据链成立的前提下，以真实瓶颈排序：

- 功能模块：每页明确用户任务、主操作、输入和输出、错误恢复；合并重复入口，不删历史功能来美化界面。优先端到端价值链“推荐 → 研究依据 → 决策 → 模拟成交 → 成本后收益 → 复查”。
- API：公共市场缓存与私有账户隔离；避免重复查询、N+1、全量返回与每个组件独立轮询。明确快照 ID、版本、时间和缺失状态。
- 数据库：先测表/索引体积、查询计划、连接池等待和 p95，再决定索引、批量读、聚合缓存和保留策略。不要无证据加索引或大幅扩容；测试分支及时按既有机制回收，不删生产账本。
- Vercel：评估实际冷启动、包大小和函数预算；不要新增常驻进程假设。低频行情不应调用 LLM。付费模型应有预算、明确终态和取消/超时边界。
- 调度：Vercel 为当前主时钟，GitHub schedule 是不准点备用。晚到必须遵守市场日历与原窗口；不允许延长窗口、增加重试或使用旧价补交易。
- 改动范围先形成有证据的优先级清单，每次只落地一个可验证切片，不开一轮无止境的全库重构。

## 7. 验收与交付

### 设计原则复核

| 原则 | 本批可验收落点 |
| --- | --- |
| 意图与主操作 | PicksBrowser 首屏推荐优先，辅助研究入口次级 |
| 认知负担 | 投资计划与逐笔记录统一入口；方法说明按需打开 |
| 状态可见 | 侧栏区分 stale/failed/unknown/disabled |
| 可恢复 | 数据缺失和错误保留具体原因与相关恢复入口 |
| 可供性 | 折叠按钮、返回按钮、徽章都有清晰动作与键盘反馈 |
| 设计连续 | 使用 TM 原语、既有 token、字体和当前页面作为基线 |
| 首次上手 | 用户不用先读手册即可找到候选和下一步研究入口 |
| 时间效率 | 恢复列表位置；一个共享状态读取；不额外调模型 |
| 信息诚实 | 百分位不是胜率；A–F 有计算规则；缺失不补零 |
| 变动可追溯 | 评级变化引用快照；时间选择不改变底层时点 |

### 必须检查的实际状态

- 中文深色主验收；英文、浅色、键盘和 reduced-motion 做受影响范围检查。
- 真实长文本、空数据、未知值、过期、失败、未登录、加载和刷新；不要只点开控件就宣布整页通过。
- 最长允许展开状态、相邻面板、后续区块、页底、侧栏折叠后的宽度。不得出现超长右侧空白、巨型 tooltip、失控 list、数字截断或页底额外滚动。
- 同页面、同尺寸、同数据条件前后截图；有限 mock 只作为明确标注的测试 fixture，不能冒充线上证据。
- 评分/评级/时区/状态聚合需要前后端契约一致。至少覆盖并列、缺失、过滤分页不改分、DST、周末/假日和主动暂停。
- 保留人类账户与 BYOK，检查私有数据权限。没有订单的运行不能标记为成交验收。
- 只跑相关测试和必要构建，失败再扩大范围；不用大量 SHA/哈希核对代替验收。

### 每个 PR 的收尾格式

简述用户问题、根因、行为变化、涉及文件、验证证据、剩余边界、部署结果与回滚方式。线上成功需要验证真实域名与受影响路径，不等于 GitHub 绿灯或 Vercel Ready。进展用简洁中文及时同步，不能只写文档不汇报。

跨层通用检查：i18n、字号、布局 shell、侧栏、时间/数据 locale、缓存与鉴权、现有组件 API。不要为每页复制一套 token 或状态判断。
