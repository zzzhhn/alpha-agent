## 预算：估算，不是实际 OpenAI 账单

价格核验：2026-11-15，官方 GPT-6.1 Sol 标准短上下文文本价格，每百万 tokens 输入 $2、缓存输入 $0.10、输出 $10。以下不假定缓存优惠；推理 tokens 包含在输出计费中，不重复加算。长上下文、工具、图片、不同服务档位不在这些估算内。

来源：[模型价格](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[订阅 API 额度规则](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)。

生产只读查询：机器人近 30 天有 16 条运行、13 次模型调用，累计输入 126,261、输出 27,011 tokens，实际模型仍是 Kimi。将这组 tokens 按 Sol 价格重新计价，得到 $0.522632，平均约 $0.0402/次。这不是已经发生的 OpenAI 费用，也不是两个模型会使用相同 token 数的保证。

| 场景 | 假设 | 每月估算 |
| --- | --- | ---: |
| 每交易日两次机器人决策 | 22 日、44 次，沿用历史平均 token 数 | $1.77 |
| 每轮都用满三次决策/补查 | 22 日、132 次，沿用历史平均 | $5.31 |
| 更保守的机器人输出预算 | 每次 20k 输入、4096 输出；44～132 次 | $3.56～$10.69 |
| 全站中等文本请求 | 每次 8k 输入、2k 输出，100 次/日、30 日 | $108 |
| 全站较大文本请求 | 每次 20k 输入、4k 输出，100 次/日、30 日 | $240 |

后两行是容量情景，不是实测流量。结论：机器人常规定时使用明显不是 $200 的主要风险；全站是否足够，取决于交互次数、BRAIN 批量评分、演化提议和推理输出。不能根据机器人一项低用量承诺全站预算够用。

当前数据库没有覆盖全站的 tokens/费用账本，近 30 天 BRAIN 有 30 轮，但没有足够 token 数据还原费用；LLM 缓存行数也不是 API 调用次数。定时行情/推荐计算不能直接按股票数当作 LLM 调用量。建议上线后用官方 Usage/Costs 对账，先观察一周；预算目标可保留 $40 缓冲，将常规消耗控制在 $160/月。预算通知不等于硬熔断，也不能假设额度耗尽后所有调用会自动停用。

## 必须逐条检查的切换面

1. 本人的全站 `user_byok`：股票简报、解释、因子研究等读取此处。原接口只保留一个全站 LLM 凭据，BRAIN 登录凭据不应被覆盖。
2. 机器人：provider/model 和 credential_source 独立保存，不能只换 Key 不换配置。配置版本更新后，旧运行不得再提交新订单。
3. BRAIN 预筛：`scripts/brain_mining_loop.py` 读取 Actions 的 `MINING_LLM_KEY/PROVIDER/BASE/MODEL`，不是自动继承设置页。这些 Secret 需要在安全流程内单独切换，不能把密钥明文放进工作流。
4. 系统环境客户端：`LLM_PROVIDER/OPENAI_API_KEY/OPENAI_MODEL/OPENAI_BASE_URL` 是另一配置来源。先确认具体活跃任务，不给别的用户替换私人 BYOK，不创建意外全站付费回退。
5. 短输出请求：persona 当前 max_tokens=300、Rich Brief=800。Sol 的推理也占输出预算；须真实验证非空完整响应，不能只做认证测试就发布全站切换。不自动加重试。

## 本批独立 Key 设计

- 既有 BotConfig 默认 `credential_source=user`，旧机器人行为不变。
- `account` 模式把密文放在 `sim_bot_credential`，按 account_id 隔离并检查 owner；不写入全站 `user_byok`。
- 凭据和配置版本在同一短事务内保存。配置快照只有来源，不含 Key、密文或 nonce。
- 专用 Key 缺失/不匹配时明确失败，不回退到全站 Key。最后使用时间只更新实际使用的那一行。
- 复用现有配置抽屉和 Tm 表单组件；输入为 password，关闭/成功保存时清空内存，不存浏览器存储。只有填入新 Key 才能一起改 Base URL。
- 切回全站模式不会删除已保存的专用 Key；删除账户会级联删除。未要求删除全站旧 Key 的外部供应商账号。
