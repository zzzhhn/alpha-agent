# 模拟仓：人类账户与自主机器人账户

版本：v1.0 · 2026-11-02

状态：首版已实现并上线。真实 BYOK 手动运行已完成；定时功能已接入，账户默认关闭。盘中真实运行和持续收益仍需交易时段观察。详见[交付与验证记录](design-system/2026-11-02-paper-bot-delivery.md)。

工程细节：[接口、数据与运行约定](design-system/2026-11-02-paper-bot-contract.md)。

## 1. 概要

模拟仓保留两个并列方向：**人类账户由用户手动交易；机器人账户由内置 BYOK 机器人自主交易**。机器人账户长期存在，每次唤起读取最新信息及已有账户状态，自行决定买入、卖出、继续持有或保持现金，不要求人逐笔批准。

首版包含定时唤起与手动唤起，并将账户、行情、推荐、订单等能力抽成统一接口。用户已确认：**先做平台内置 BYOK 机器人，接口预留外部接入，首版不开放外部机器人凭据**。

### 已确定与待验证

| 类型 | 内容 |
| --- | --- |
| 用户已确定 | 人类/机器人账户分开；持仓持续存在；支持定时与手动唤起；机器人自主决定交易，无逐笔人工审批；复用现有 UI 和 BYOK |
| 本稿建议默认值 | 每人先有一个机器人账户；开盘后 30 分钟、收盘前 30 分钟各唤起一次；首版美股/ETF、只做多、不杠杆；允许不交易 |
| 工程必须验证 | 盘中数据时效与来源；所选 BYOK 模型单轮耗时；调度迟到率；公司行动与价格复权口径；部署后的成本和容量增量 |
| 当前不做 | 实盘券商连接、外部访问 token、机器人群聊/辩论、多机器人竞赛、期权与杠杆、自动重置账户 |

建议默认值不是用户已批准的交易策略，也不是经实测证明最优的参数；创建时可见、可调整。文档先于功能实现，不能据此声称已有可运行 bot。

## 3. 背景

刚上线的模拟仓已整理了个人账户摘要、推荐与下单双栏、持仓归因、净值和订单，但仍是人工操作入口。用户希望平台持续运行一个虚拟投资账户，自己不用每天守着点击，也能观察 AI 是否具有实际的组合管理价值。

这不是“每次生成一个新组合”的临时实验。一次唤起是一个 **run**，不是一个新账户；某只股票可以跨几十轮继续持有。机器人必须知道之前为什么持有、现在发生了什么变化，以及已有订单是否尚未成交。

### 当前实现核验

| 现有能力 | 可以复用 | 需要改变 |
| --- | --- | --- |
| BYOK 服务端凭据与模型适配 | `api/byok.py`、统一 `LLMClient` | bot 显式绑定 provider/model；后台任务不能依赖浏览器在线，不能随“最近保存的 key”悄悄换模型 |
| 模拟账户、持仓、订单、费用、资金预留 | `api/routes/paper.py`、`sim_*` 表 | 目前 `user_id` 唯一，需支持账户类型并完整隔离查询、权限、重置和下单 |
| 模拟撮合 | `paper/fill_engine.py` 与 cron | 现有市价单按下一交易日收盘成交，不适配盘中唤起；不能原样套用到 bot |
| 行情 | `daily_prices`、有限分钟数据、股票与推荐接口 | 推荐展示的价格主要是最近日收盘；分钟缓存不是覆盖全市场的可靠实时 feed |
| 长期净值 | `sim_equity_daily` | 当前撮合在无可处理订单时提前返回，跳过之后的净值写入；估值必须独立于交易 |
| 持久化后台任务 | proposer 的入队、runner 与用户 BYOK 模式 | 复用模式而非照搬旧任务；增加 bot 的运行状态、预算、恢复和交易日调度 |

旧 `/api/decision` 面向默认单个 ticker，并依赖旧模型训练/融合路径，不直接作为新 bot 的大脑。这里只复用有效底层能力，不以“已有 LLM 决策”推断它能管理持续账户。

## 4. 目标与成功标准

### 核心目标

用户设置一次，平台在每次唤起时完成“了解账户 → 研究当前信息 → 自主行动或不行动 → 记录结果”，跨日持续运行；用户随时能看懂它在做什么、持有什么、表现如何。

### 首版验收目标

- **持续性**：至少跨三个交易日验证同一账户、现金和持仓连续存在；刷新页面、部署、重新唤起不新建或重置账户。
- **完整链路**：手动与定时均能完成含真实 BYOK 的一次运行；成功不交易与交易待成交都被正确解释。
- **无人值守**：启用后不要求每轮确认；配置失效、行情不可用等有明确恢复入口，不靠用户猜测。
- **交易真实性**：决策与成交时间有先后，价格来源、费用、交易状态可追溯，不使用已知旧价格伪装盘中成交。
- **可比较**：每个已完结交易日有估值或明确缺价标记；净值、交易成本、模型开销及基准口径分开呈现。
- **资源有界**：首批五个交易日实测模型耗时、调度迟到、数据库/网络增量；公布观察值，不在上线前捏造容量或盈利指标。

观察期记录“应唤起次数、实际开始次数、迟到/跳过次数、有效决策次数、成交完成率”，不能只看任务 HTTP 成功率。样本不足时不宣布策略有盈利能力。

## 5. 用户与使用场景

首位用户是使用桌面端的个人研究者。其工作不是监管每笔交易，而是设定实验条件、偶尔主动唤起、查看长期表现和理解异常。

典型场景：

1. 第一次配置已有 BYOK，创建机器人账户并开启两个每日时段。
2. 几天后回来，看到原有持仓仍在，并能查到每次加减仓或继续持有的理由。
3. 发现新信息，点击“立即唤起”；机器人重新检查账户，不重复买入已挂单的股票。
4. 想更换模型，修改配置后从下一轮生效；账户及历史业绩不清空，并标记策略版本变化。
5. 暂停自动运行，但继续看持仓与净值；暂停不等于清仓。

约束：个人项目、有限数据库和算力；不添加常驻行情终端、全市场分钟级轮询或多模型辩论作为首版前提。

## 6. 价值主张

- **从建议到持续行动**：平台不止告诉用户哪些股票值得看，而是维护一个可持续观察的虚拟账户。
- **自由决策，执行有规则**：模型决定交易意图，平台保证账户隔离、现金和股数正确。模拟不用逐笔审批，但仍不能乱记账、重复下单或无限消耗 API 额度。
- **研究可复查**：每次运行展示简短决策摘要与证据；保留长期持仓理由，不把长对话或内部思维过程当作账本。
- **用真实对照判断增益**：既看市场基准，也看同条件无 LLM 规则组合，区分模型判断、市场上涨和高仓位带来的收益。

不承诺机器人会赚钱。首版要让“有没有价值”变得可测，而不是先让报表看起来赚钱。

## 7. 解决方案

### 7.1 产品与 UI

**保留** AlphaCore 壳、侧栏 `/paper`、字体、配色、TM 组件与刚精修的人工交易流程。**精修**账户切换、上下文与账本。**替换**仅发生在机器人视图：右侧手动下单票据换成运行面板，左侧推荐列表换成“本轮决策与账户持仓”的主工作区。

页面关系：

```text
模拟仓                                      刷新  配置
人类账户  |  机器人账户

机器人名称 · 模型 · 运行状态 · 下次唤起        [立即唤起]
账户净值              可用现金        未实现盈亏         总收益

本轮决策 / 持仓变化                 │ 运行面板
买入、卖出、持有或不操作             │ 定时：开盘后 / 收盘前
简短摘要 + 来源时间                  │ 最近运行 / 下次计划
查看依据 → 详情抽屉                  │ 暂停定时 / 配置

当前持仓                            │ 模拟净值与基准

运行记录  |  订单成交  |  费用           分页，默认 5 条

▸ 系统策略验证（独立研究账本）
```

人类账户沿用当前推荐与票据布局。两个账户切换后，摘要、持仓、净值、订单必须全部同步切换；不允许标题换了而表格还显示另一账户。

#### 关键交互

| 状态/动作 | 页面行为 |
| --- | --- |
| 尚无机器人 | 不自动创建；显示“创建机器人账户”，一次配置已有 BYOK、名称、本金、策略说明和两个时间点 |
| 已创建，未运行 | 保留空账户，不制造收益；主按钮“立即唤起” |
| 空闲，可运行 | 显示准确的下次计划与交易日；“立即唤起”为唯一填色主按钮 |
| 正在运行 | 原位显示“读取账户 / 分析 / 提交 / 等待撮合”；禁重复唤起，刷新或离开不终止任务 |
| 本轮无交易 | “本轮保持持仓”或“本轮继续空仓”，附简短理由；不是错误，也不显示假订单 |
| 已提交，待成交 | 明确显示待成交数量与原因，不显示“交易完成” |
| 部分完成 | 已成交、待成交、被拒分别列明；只处理剩余部分，不重跑整批已成交订单 |
| BYOK 失效/预算耗尽 | 保留账户与历史；就地链接设置或预算，不自动换模型/key |
| 行情缺失/超时 | 显示受影响标的与数据时间；未受影响持仓仍可查看 |
| 暂停 | 停止后续决策与尚未提交的动作，保留持仓；已受理订单继续按订单规则处理 |

“暂停定时”关闭自动唤起，但保留手动唤起。“停止本轮”阻止该轮尚未提交的动作，不撤回已成交订单。“撤销待成交订单”和“重置账户”是独立操作，后者需要明确确认并保留历史 cohort。

配置用 560/720px 的现有 `TmDrawer`，分“模型与策略、唤起时间、运行额度、模拟规则”四组。高级设置折叠，主画面不堆长说明。行情、订单和运行详情复用抽屉，短提示最多解释一个概念，不再出现整屏长 tooltip。

复用 `SegmentedTabs`、`WorkbenchHeader`、`TmPane`、`TmButton`、`TmTable`、`TmPagination`、`TmStatePane`、`PaperCurvePane` 和 `PaperOrdersPane`；业务组件新增不意味着新造一套原子组件。切换和分页只使用短淡入，无位移、弹跳或逐字财务数值动画。

### 7.2 功能与业务规则

#### A. 账户长期存在

- 首版每位用户保留一个人类账户、一个机器人账户；结构允许将来扩展多个机器人，不提前做复杂管理器。
- 两账户可设相同虚拟初始资金，但不共享现金、持仓、挂单或盈亏。
- 唤起、暂停、修改模型、修改时间表均不重置账户。
- 标的退出推荐榜不自动平仓，到了某个持有天数也不默认强制卖出；每次由机器人结合持仓与证据复核。只有用户明确配置的规则才成为强制约束。
- 长期记忆由账户事实、逐标的持仓理由、最近几轮摘要组成；不依赖永不截断的聊天记录。
- 用户策略说明是偏好，例如投资范围、持有风格和集中度；模型可自行买卖，但不能修改平台执行限制或预算。

#### B. 机器人可以读取和操作什么

| 能力 | 首版范围 |
| --- | --- |
| 查标的 | 搜索平台支持的股票/ETF，返回稳定标的身份、交易所、币种、是否可模拟及不可用原因 |
| 查推荐 | 最近有效推荐、排名、评级、来源快照、数据时间与限制；不只看到前端显示的 5 只 |
| 查行情 | 有来源与时间戳的日线、按需盘中数据；缺失或延迟明确标注 |
| 查研究 | 平台已存的信号、有限相关新闻摘要和证据，不为每轮重新做全市场研究 |
| 查账户 | 现金、可用现金、持仓、已有挂单、成本、历史成交及当前执行能力 |
| 自主动作 | 买入、卖出、继续持有、保持现金；撤销尚可撤销的 bot 挂单；保存简短持仓理由 |
| 不开放 | 访问其他账户、读取密钥、提取真实资金、修改预算/权限、清除历史、调用实盘券商 |

默认给“当前持仓 + 推荐前 20 个”的精简输入，机器人可通过受限查询工具查更多平台标的，并不强制只能买 Top 5。股票池、最大持仓数和读取次数是创建时可见的配置；首版只做多、整股、现金约束，不解释为真实券商购买力。

新鲜度按数据类型和交易日判断：上一交易日推荐可作为今天的研究依据，但不能充当今天的成交价格；周末经过 24 小时不自动等于推荐失效。交易必须另有符合执行规则的盘中行情。

每个账户的 capabilities 接口返回当前允许的动作、订单类型、撮合模式、价格要求和额度。模型不能凭提示词猜接口是否支持，也不因同一个按钮而获得人类账户的操作权。

#### C. 定时与手动唤起

默认两个独立开关：**开盘后 30 分钟**、**收盘前 30 分钟**。按交易所日历及 `America/New_York` 计算，不写死北京时间；页面同时显示当地时间、北京时间与所属交易日。

普通交易日对应美东 10:00、15:30。冬令时对应北京时间当日 23:00、次日 04:30；夏令时对应当日 22:00、次日 03:30。提前收市日跟随实际收市时间，休市日不自动启动。NYSE 官方日历包含正常时段和提前收市安排。[官方交易日历](https://www.nyse.com/trade/hours-calendars)

手动按钮的含义是“现在让机器人自主运行一次”，不是“生成一个待批准的计划”。休市时仍可唤起研究并更新持仓理由，但首版不交易、不自动预约一份过夜旧计划；下一交易日重新读取信息后决策。

同账户同一时刻最多一轮运行。重复点击返回已有 run；定时与手动碰撞时合并到在途运行并注明两个触发来源。下一时段只有上一轮已结束后才进入；不积压多轮旧任务。

GitHub 定时任务可能延迟甚至漏触发，不能承诺精确到分钟。[GitHub 官方说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) 首版采用“计划窗口 + 真实开始时间 + 过期跳过”，建议可迟到窗口 15 分钟；过期不回填历史订单。页面展示计划与实际两种时间。

#### D. 一次唤起的流程

```text
定时 / 手动
    ↓
创建或复用 run，锁定账户与配置版本
    ↓
读取账户、挂单、推荐、行情、持仓记忆
    ↓
BYOK 分析；必要时按限额补查平台数据
    ↓
结构化决定：买 / 卖 / 持有 / 不操作
    ↓
程序核验数据、权限、现金与数量
    ↓
自动受理订单或记录不操作；不经过人工审批
    ↓
获取决策之后的行情，模拟撮合并更新账本
    ↓
保存简短理由、证据和费用；每日另行估值
    ↓
等待下一次唤起，账户与持仓继续存在
```

模型负责意图与依据，程序负责股数换算、费用、现金预留、订单状态和账务。预算不足、数字非法或数据不可用时给出明确拒绝原因；不是默认转成人工审批。

卖单未成交前，预计收入不能当作可用现金。允许机器人给出依赖卖出现金的买入计划，但执行器必须先确认卖出完成，再重新检查价格与现金；超出运行期限的余下计划失效，不在几天后悄悄执行。

#### E. 盘中模拟成交

建议给机器人增加独立的 **`intraday_next_bar_v1` 分钟级模拟模式**，不改动既有人类订单和历史成交规则：

1. 订单接受时记录真实 `accepted_at`、标的、现金预留和执行模式，不立即用模型输入价格结算。
2. 首版市场单使用 `accepted_at` 之后第一根完整分钟 bar 的开盘价作为仿真参考，加上明确费用/滑点模型；bar 的起点必须晚于订单接受时间，不能复用接受前的那根 bar。
3. 等该分钟数据实际可获取后才确认成交，保存该 bar 的起止、来源与取得时间。等待中显示待成交，不能假装是实时交易或真实盘口成交。
4. 若没有合格的盘中数据，拒绝或到期取消该订单，释放资金；不静默退回昨日收盘价、输入快照价或次日收盘模式。
5. 限价单首版暂不向机器人开放，避免将“触及 high/low”直接当成真实可成交。人类现有限价功能保持原样。

这是一种透明的简化仿真，并不模拟盘口排队、成交深度或真实券商执行。其上线前提是对少量标的实测可取得足够及时的分钟数据；不满足时先接合适的数据来源，不能以“功能上线但几乎永远不成交”冒充完成。

现有人类新订单费用是单边 10 bps；建议 bot 初始沿用该费用假设，再加单边 5 bps 的不利滑点作为可见、可配置的初始实验假设。两项分别计入并展示，不宣称等同真实佣金或已测得市场冲击。后续调整只影响新订单，历史不重算。长期持仓必须核对拆股、分红、停牌、退市及代码复用；不把股票代码直接等同永久资产身份，不混用复权价格和原始成交价。

#### F. 持续记忆、记录与评估

- 下一轮必读账户真实状态与未成交订单；前一轮计划不是事实来源。
- 每只持仓保留简短 thesis、最近复核时间、证据引用与改变看法的条件。旧摘要可压缩，但成交与账户事实不被模型摘要覆盖。
- 保存可供用户阅读的决策理由，不要求或记录内部思维链。模型不能把无来源的主观叙述写成市场事实。
- 不交易日照常估值；缺价标记 stale/partial，不凭空补零收益。不能只有成交日才有净值点。
- 首版展示净值、成本后收益、市场基准、回撤、现金占比、换手与持有期限；模型费用单独列出，金额未知时显示 token 用量和估算标记。
- 人类账户与 bot 账户若使用不同成交模式，不能直接作优劣结论。模型增益对照组必须采用同样信号时间、候选集、资金、费用和分钟撮合规则。
- 模型/策略/费用变更标在曲线上，不把不同实验条件无缝拼成“同一策略历史”。

### 7.3 技术与资源约束

#### 少量新增结构，共用账本

扩展 `sim_account` 的类型与名称；保留 `sim_order`、`sim_position`、`sim_equity_daily`。新增 bot 配置和运行记录，订单补充 run、时间戳、执行模式与价格证据。现有 `/api/paper/*` 无 account 参数的入口继续指向人类账户，避免旧页面误写机器人账户。

先提取共用账户/下单服务，再让人工 API 和 bot 调用。每个入口都验证 owner 与账户类型；数据库能保存不代表该用户或机器人有权限操作。

#### 模型与后台任务

浏览器只入队并查询状态，关闭浏览器不终止任务。runner 分阶段推进持久化 run，不依赖 Vercel 响应结束后的后台协程；模型密钥仍留在后端，不复制到前端、GitHub 日志或 run payload。

复用所选 provider/model，不强迫更换模型，不以 60 秒统一超时掩盖慢模型正常响应。实际每轮读取和重试要受已核验的部署时限约束，单轮模型请求不能靠“分阶段队列”凭空突破函数上限。Vercel 文档区分不同计划与 runtime 的时长限制；需核对项目实际配置，不能从通用文档推定账户当前额度。[官方限制](https://vercel.com/docs/functions/limitations#max-duration)

建议先一轮主调用，至多两次按需补查/决策续轮，总运行预算约 12 分钟并受闭市截止约束。若选择的模型单次调用稳定超过可用后端时限，需要另行确定长任务执行环境；不得暗中更换模型或把 BYOK 主密钥迁出后端。

#### 不再次撑爆容量

- 一个共享调度入口，不为每个用户创建一个 GitHub workflow；首版串行处理少量 bot。
- 只按需请求候选与持仓的盘中数据，不启动全市场分钟行情归档。模型等待时不占用数据库连接/事务。
- 每 run 存有界的输入快照、结果、必要行情证据与引用。只保存实际成交所需的分钟 bar，普通市场数据用短期共享缓存。
- 建议每个 bot 每交易日 2 次定时、额外手动次数可设上限；调用/输入输出 token 为硬预算，金额只有可靠单价时才可作为估算阈值。创建时用户确认预算，不在本轮发起消费。
- 详细非交易诊断建议保留 90 天、摘要长期保留；成交、余额与必要审计证据不随诊断清理删除。清理策略实现前单独检查引用关系，不删除现有用户历史。
- 数据库空间、网络出口、runner 时间和模型额度分别监测，不能只盯 storage。已有 preflight 机制可复用，但新 bot 需核验它覆盖的实际资源。
- 已知的凭据失效、市场关闭、预算耗尽等记为产品状态，不让正常跳过变成重复失败邮件。系统故障仍明确告警，不能用 `continue-on-error` 掩盖；通知按状态变化去重。

### 7.4 假设与验证事项

| 假设/风险 | 上线前怎么确定 |
| --- | --- |
| 当前数据源足以支持少量标的的盘中模拟 | 在正常交易日分别采样开盘后与收盘前，检查原始价格、时间戳、延迟、缺失与限流；不为验证批量抓全市场 |
| 既有模型适合结构化组合决策 | 使用用户选定 BYOK 完成少量真实受控运行，检查格式、耗时、持仓记忆、工具预算；不只用 mock 宣称已跑通 |
| 可依赖现有 runner | 观察两个时段的计划/实际开始时间、重复唤起与任务恢复；迟到可见且不会补做历史交易 |
| 现有价格适合长期持仓 | 分别核验原始/复权口径、拆股和分红；异常冻结受影响标的并解释，不自动重命名或清仓 |
| 可将行情提供给所选模型 | 核对数据供应商与所选模型的使用范围。yfinance 项目提示 Yahoo 数据面向个人用途，不能据此推断已获商业再分发授权；首版不开放公共数据转发接口。[项目说明](https://github.com/ranaroussi/yfinance) |

## 8. 落地顺序与发布

下列是实现批次，不代表本稿已完成这些功能，也不承诺未经验证的工期。

| 批次 | 交付物 | 完成条件 |
| --- | --- | --- |
| A：账户与成交基础 | 双账户兼容迁移、共用服务、盘中数据小样验证、执行/费用口径、无交易日估值 | 人类旧数据不变；机器人账户独立；分钟成交链路具备真实数据证据 |
| B：手动唤起闭环 | BYOK 绑定、context/tools、持久 run、结构化动作、自动订单与长期记忆 | 点击一次可自主完成交易或明确不操作，刷新/离页不丢失；真实模型验证通过 |
| C：定时与 UI 整合 | 两个交易日时段、暂停/恢复、漏触发处理；现有页面内账户切换、运行面板、详情抽屉 | 盘前/休市/半日市/夏令时处理正确；桌面同页面前后对比可评审 |
| D：小范围上线观察 | 一位用户、一个 bot，监测若干交易日，提供净值与运行回执 | 实际调度、数据时效、账务、容量与模型成本可解释，无重复下单和邮件轰炸 |

B 和 C 的界面可在同一 feature 内并行成形，但不发布“按钮可点、后端闭环未通”的壳。首版包括自主执行，不以长期人工审批替代验收。启用仅发生在用户配置并点击启用后。

后续再做多 bot/模型对照、外部 agent 访问 token、限价/更真实流动性仿真、更广泛数据与资产。新数据订阅、额外执行环境或扩大凭据访问范围需要单独确认，不默认为本功能授权的一部分。

### 适度验收清单

1. 账户隔离与旧接口兼容；机器人不可操作人类账户或他人账户。
2. 定时/手动重复唤起不重复下单；崩溃恢复识别已提交/已成交结果。
3. 不交易、行情过期、资金不足、部分成交与取消语义正确；不得以成功 toast 代替持久结果。
4. 下一轮读取真实持仓及挂单，卖出现金未到账前不超买；数据或配置过期不补做旧计划。
5. 无交易日估值连续，费用和公司行动口径明确，基准与 bot 不混用不同执行规则。
6. 实际桌面 UI 检查账户切换、抽屉、分页、中英/深浅主题；保留现有视觉，淡入不位移，不出现双层页面空白滚动。

只测变更相关的业务闭环，不为文档跑全量构建、制造大量模拟订单或反复核对 SHA。技术验证、真实运行、视觉认可与正式部署分别记录。
