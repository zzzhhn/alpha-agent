# 警报页局部精修：待视觉审阅

## 范围

沿用现有三栏工作台、暖纸色／深色主题、字体与 TM 控件，不替换导航、数据源、排序算法或交易行为。用户要求先看同页前后对比，本轮不推送、不合并、不部署。

使用任务：在有限时间内找到与持仓／候选相关的变化，核对证据，再决定处理、暂缓或进入研究。

## 已落实

| 原页面摩擦 | 精修结果 |
| --- | --- |
| 侧栏约 300px，列表很长，详情动作在下方 | 筛选栏收窄至 184px；保留列表与详情；动作放到详情顶部 |
| 一次铺开 28 条待处理记录 | 每页 5 条，可搜标的或变化；保留全部载入记录及原排序 |
| 5 列重复解释挤占空间 | 每条按标的／等级／时间、变化、关联／证据三行呈现 |
| 多条类似事件难区分 | 显示实际日期与时间，保留相对时间，不擅自合并事件 |
| 空筛选仍可能显示先前选中项 | 详情仅从当前页选取；空结果清空详情并提供清除筛选 |
| 历史记录写成“今天关键变化” | 改为“待复核”；旧源明确标识历史记录 |
| 读取时间被当作数据新鲜度 | 分开“最新事件”与“队列更新”，保留事件日期 |
| 没有操作也显示“完成分诊” | 无更新时间时显示“尚未处理”，不伪造处理时间 |
| low、open、n_24h 等原始字段 | 已知置信等级、状态与证据字段本地化；未知字段保持原值 |
| 审计列表继续拉长页面 | “处理记录”按需展开，有界滚动；准确说明是载入事件的最近状态，并非完整审计日志 |
| 乐观操作失败回滚可能改写更新时间 | 成功使用服务端返回状态；失败恢复完整旧状态 |

分页只使用 140ms 淡入，不做位移。没有新增依赖、数据库查询或接口轮询。

## 原则复查

| 原则 | 本轮对应 |
| --- | --- |
| 意图对齐 | 搜索与队列帮助找到事件，右侧直接提供处理动作 |
| 认知负担 | 精简为三行摘要；细节留在右栏 |
| 状态可见 | 刷新 loading、准确的空筛选、选中状态和数据时效 |
| 可恢复 | 保留撤销；失败恢复完整原状态 |
| 可操作性 | 复用 TmButton、TmSelect、TmInput、TmPagination |
| 设计服务任务 | 不引入新风格或装饰性图形 |
| 易理解 | 状态／置信度中文化，不用操作说明解释布局 |
| 尊重时间 | 五条分页与即时本地筛选；无新增网络调用 |
| 数据诚实 | 不再将历史事件称为今日新增，不伪造分诊完成时间 |
| 明确主操作 | 详情内唯一实心主按钮“标记已处理” |
| 可追踪性 | 保留事件时间、结构化事实、最新处理状态与关联对象；不推断因果 |
