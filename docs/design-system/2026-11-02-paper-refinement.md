# 模拟仓原位精修

## 目标与边界

桌面用户先核对个人账户，再从推荐创建订单，最后查看成交、持仓与净值。保留 AlphaCore 壳、字体、配色、TM 组件及左右双栏；不重做导航、不换页面风格、不更改成交规则。先交付同一页面、同一组只读数据的前后对比，模拟仓改动未获视觉认可前不合并上线。

当前问题来自真实页面：重复引导挤占摘要；窄下单区自由换行；个人净值旁混入系统验证账户并撑高整行；空态指向旧标签；加载误报空记录；来源请求失败遮住有效持仓；清除选择自动反选第一只。

## 改动

- 账户摘要保留四项，使用真正的 available_cash；未知显示破折号，零收益用中性色。重置操作保留二次确认，移入账户与规则。
- 推荐与下单沿用两栏。推荐按钮表达“选择”，独立下单按钮才提交；票据布局复用 SimOrderForm，其他入口默认布局不变。
- 清除选择保持清空，带入的 ticker 不在短名单时不偷偷换成第一只；刷新时禁用提交。
- 个人持仓、个人净值和最近订单连续排列；来源缺失不遮住持仓、不冒充自主交易。系统研究验证按需展开，与个人收益明确分离。
- 最近载入的 20 笔订单默认 5 条分页，范围说明不暗示完整历史。空态说明下一步，不制造收益曲线。
- 翻页动画按用户反馈仅保留淡入，去掉 translateY。

## 约定核验

复用 `useLocale`、`sim.*` 文案、locale-aware 公司名称；新增文案均提供中英版本。保留 `font-tm-mono`、`font-tm-serif`、TM 颜色与字号；继续使用 WorkbenchHeader、TmPane、TmTable、TmPagination、TmStatePane、TmButton、TmDisclosureButton。`/paper` 路由与侧栏不变，无新图标、样式依赖或数据库变更。

## UX 原则核验

| 原则 | 落点 |
| --- | --- |
| 意图对齐、减少认知负担 | PaperScreen 保留推荐与下单邻接，系统账本独立折叠 |
| 状态可见、尊重时间 | 首次读取显示 loading；刷新状态可见且冻结提交 |
| 可恢复 | 清除选择有效，局部错误可重试，重置仍需确认 |
| 可供性、一个主要操作 | 推荐仅“选择”；唯一主按钮为提交模拟订单 |
| 设计隐于任务、无需说明书 | 固定票据字段，删除重复步骤横幅，空态指向实际下单区 |
| 真实、可追踪 | 来源未知保留未知；个人与系统收益分离，缺数不造零 |

## 验证与交付

用 2026-11-02 线上只读响应捕获建立本地前后基线。保留真实空账户，不伪造持仓或盈利；本地服务拒绝所有写入，凭据不复制。截图与浏览器记录存于本轮 paper-refinement-20261102 工件目录。技术验证与用户视觉认可分别记录。

已完成：TypeScript、7 项相关测试、设计系统审计；浏览器核对选股/清除、空态焦点、限价字段、系统账本折叠、中英深浅主题及 1100px 桌面横向边界。较窄桌面的推荐操作列保持固定，横向浏览时仍可选择。尚未验证真实订单成交，因为本轮只读预览不得改变账户；生产模拟仓未更新，等待用户审阅。

## 后续议题，不在本轮实现

用户提出 bot 自动模拟投资，可复用 BYOK。下轮讨论执行授权、成本/频率上限、可暂停性、订单与决策日志、个人账户与独立试验账户的边界。本轮不创建 bot、不调用 LLM、不自动模拟成交，也不添加不可用占位按钮。
