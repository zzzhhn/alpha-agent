# 机器人唤起可靠性与漏跑提示

## 原因与边界

11 月 6 日开盘轮次：GitHub schedule 在 10:02、10:12 ET 的预期事件均未在 10:20 ET 的准入截止前出现。没有新 run，也没有 BYOK 调用。后端与盘中 SPY 探针正常，不能把这次没有交易解释为模型主动观望。GitHub 内部未派发原因没有可验证结论。

另一个确定缺口是调度观察记录由执行器写入：执行器完全没有到达时，原界面不会显示漏跑。修复不改变策略、凭据、人类账户或现有资金账本。

## 唤起与执行

- 复用现有 Vercel Pro Cron，以 `CRON_SECRET` 保护 `GET /api/cron/paper_bot/wake`。
- Vercel 只检查时段、入队和派发。模型与撮合继续使用 GitHub 有界 worker，不在短 HTTP 请求内后台空跑。
- UTC `1,4 14,15 * * 1-5` 覆盖夏令／冬令开盘后 31 与 34 分钟；`31,34 16,17,19,20 * * 1-5` 覆盖半日／正常收盘前 29 与 26 分钟。交易日历和原 20 分钟窗口过滤无效时段。
- 共 12 次短检查／工作日，不是全天分钟轮询；正常交易日只有开盘和收盘的有效窗口可能创建任务。
- GitHub 原定时入口保留。多入口共享 `account:session:slot` 唯一键和运行租约，不能重复创建决策或订单。
- 派发失败返回明确 503，记录安全的派发状态，保留队列供下一次入口接管。不得记录 token、BYOK 或完整模型提示。
- 这是独立定时入口，不是独立执行平台。GitHub 执行服务本身不可用时仍会阻塞，不能声称完全容灾或严格准时 SLA。

## 读侧状态

- 按当前配置生效时间推导最近有限时段；不追溯猜测旧配置。
- 未到时间为“尚待窗口”，窗口内未入队为“等待触发”，超过窗口为“错过窗口”。
- 实际 run 高于观察表：即使入队成功后观察记录写入失败，也不能误报漏跑。
- 推断状态明确标记，缺失观察时间保留 `—`，不补造执行器回执。
- 保留现有运行面板和抽屉，在面板增加漏跑提示；闲置但定时启用时每分钟读取轻量状态，隐藏标签暂停，已有运行沿用原轮询。
- 读操作不补跑、不下单。手动验证始终标记 manual，不覆盖开盘漏跑事实。

## 验证范围

针对性覆盖：缺失触发、窗口边界、配置生效前不产生义务、周末、实际 run 优先、鉴权、无任务不派发和派发失败。部署后检查生产路由、Vercel cron 定义、界面状态，再进行一次已授权的真实手动 BYOK 验证。只有发生订单并核对终态，才能宣称线上撮合已实测。
