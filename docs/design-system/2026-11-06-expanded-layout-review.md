# 展开态布局修复与审查漏项

日期：2026-11-06，Asia/Shanghai。延续 integrate-design 和现有 TM 界面；用 error-analysis 扩展既有事故目录，不新建第二套设计体系。

## 问题和边界

用户的 Data 截图不是下拉菜单定位问题，而是 **左侧披露明细决定整行高度**。生产页的价量、元数据、基本面和缺价列表同时展开时，两个网格子区都高 1,383px；右侧成分股目录只有约 300px 内容。上一轮虽有点击与键盘回执，却没有以整个视口复核这种组合状态，属于主代理验收漏项。

保留：壳、字体、颜色、数据、搜索筛选、分页、TM 原子控件。精修：长证据与短概览的布局关系。替换：卡片里的长内联详情改为既有对话框。无后端、BYOK、账户、定时配置或交易逻辑改动。

## 实施

1. Data 顶部只保留紧凑概览和成分股双栏。覆盖明细在两栏下方全宽呈现，不再拉高邻栏。
2. 四个覆盖分组同一时刻只开一组；基本面每页 8 个字段，缺价每页 6 只，保留全量计数与最后一页访问。
3. 算子／操作数目录沿用 8 项卡片目录，详情在共享 TmDialog 阅读，Escape 和关闭按钮回到原卡片；切换筛选或分页不遗留旧详情。
4. Methodology 的管线来源独立全宽显示；偏差防护和板块作为短内容双栏，来源披露不会撑高它们。

没有全局修改 TmCols2，也没有用 overflow:hidden、截断证据或 items-start 掩盖网格空白。

## 以后怎样避免

审查清单分两列：**动作结果**与**展开后的整页构图**。至少检查最长一个详情及允许的多项展开组合，记录邻栏尾部、后续章节、主／局部滚动及焦点。同尺寸、主题、语言与数据比较；变长证据若不是并排比较任务，优先全宽、分页或抽屉，不为了维持双栏而创造整屏空白。
