# 设计系统复审与标准化

## 结论

复审前不能声称全部生产设计都来自设计系统。原审计覆盖原生控件、图标和最低字号，但漏掉了 TypeScript 内的文字透明度、SVG 字号属性、硬编码热力色阶、自建弹窗，以及缺少真实样例的服务状态和通知。

本轮沿用现有 Workstation 风格，补齐实际共享实现与审计，不重新选择视觉风格，也不修改量化指标或数据口径。

## 修复清单

| 表面 | 原偏差 | 标准化结果 |
| --- | --- | --- |
| 报告深度弹窗 | 自建遮罩、关闭事件，没有统一焦点管理 | 使用生产 `TmDialog`；仅保留报告内容需要的宽度 |
| 通知 | 两个原生按钮、不同圆角、未本地化关闭操作 | `ToastView` 共用 TM 控件、字号、阴影与语言上下文；参考页实际触发、关闭通知 |
| 遮罩与阴影 | 各处黑色透明度和阴影自由定义 | `--tm-scrim` 与两级阴影令牌覆盖对话框、抽屉、提示、选择菜单、通知和引导 |
| 评级与归因行 | C/C+ 等评级只剩 25% 至 45% 的文字可见度，整行被淡化 | 保留完整语义文字颜色，用表面与权重区分强调程度 |
| 字号角色 | 18 个文件存在 12.5/13/15/17/20/22/26px 局部字号 | 统一为 12/14/16/18/24/28px 层级，并把强调正文、紧凑标题、关键指标与重点对象加入参考 |
| 月度热力图 | 另一套 HSL/RGB 调色板，浅色块可能配浅色文字 | 共享 `tmHeatmapColor` 与前景色，月份随语言切换 |
| 亮色主题 | 警告色以及部分悬停背景上的弱化/信息文字未达到 AA | 调整相应语义色，56 组实际主题颜色组合通过 4.5:1 检查 |
| 服务状态 | 生产壳层自有状态标记，没有参考样例 | 提取 `TmServiceStatus`，检查中、正常、降级、不可用共用组件 |
| 图表参考 | 除雷达外主要是示意图和名称登记 | 补入真实月度热力图、回撤、净值对比组件，示例数据明确标记 |
| 资产迁移台账 | 通知例外和迁移描述滞后 | 22 项台账，原生控件例外从 3 个减为 1 个 |

## 保留的受控差异

- 不同业务图表保留各自的坐标、数据形状与任务布局，共用语义色、字体和交互规则。不能因为都属于图表就强行变成同一张模板。
- driver.js 的目标定位、少量兼容原生 title、月度热力矩阵的原生 table 语义，以及已停止页面加载的旧图表，均保留明确登记。
- 图表“已登记”不等于所有状态都具备可运行样例；台账继续显示这一区别，不把登记数量当成全面完成率。

## 防回退

`audit-token-contract.mjs` 补充扫描 `.ts` 和 `.tsx`，检查颜色硬编码、低透明度文字、非标准大圆角、绕开 TM 的对话框、SVG 小字号，以及令牌漏登记。它还根据实际主题 CSS 计算文字对比度。原有图标/控件/页面结构审计继续运行。

可复用验收命令：`npm run audit:design-system`。生产路径与浏览器结果在本轮交付中核实；不以静态规则 0 报错代替视觉和交互验收。

## 原则检查

状态明确且不伪装实时数据；示例与生产组件同源；原有模块任务布局保持差异；字色清晰；颜色不单独传达状态；可键盘触发提示与关闭浮层；错误只影响对应面板；主题与语言切换保持一致；参考样例不发起交易、LLM 调用或账户变更。

## 本轮验证

本地设计审计覆盖 15 个页面、20 个令牌与 56 组文字对比度，全部通过；73 项前端测试通过。浏览器验证了真实通知的触发与关闭、弹窗焦点和 Escape 恢复、实际图表样例以及中英文和明暗主题。语言切换时发现的 React 更新警告也已修复。后续图表状态样例仍按台账逐项扩展，不宣称所有业务状态均已目视验收。
