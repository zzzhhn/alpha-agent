# 侧栏双语命名、真实状态提示与折叠

日期：2026-11-11。范围：路线图 NAV-1～NAV-3。原页精修，沿用 TM 组件、字体、配色与现有路由；没有新视觉体系、动效库或数据库迁移。

## 用户问题与根因

- 侧栏名称靠 `lifecycle.*` 混合字符串（如“因子 Alpha”），而另一部分只有单语，切换语言后层级与重复都不一致。
- 侧栏没有任何业务状态；全局只有“系统运行正常”，`/api/_health/dag` 用“30 小时内是否有发布”判断，11-10 交易日缺发布时仍显示 healthy。
- 桌面无法折叠。

## 行为变化

1. **双语**：`lib/nav-items.ts` 为 15 个路由分别保存 `zh` / `en`；当前语言在上、另一语言在下，同为 12px mono，不缩小英文。组标题单语单行，读屏使用双语名。子路由（如 `/paper/...`）保持父项选中。
2. **状态契约**（只在能指向下一步时显示）：
   - 今日推荐：`GET /api/nav/status` 按 XNYS 最近完成交易日判断：`current` / `awaiting_publish`（收盘后 23:00 UTC 起 3 小时宽限内）/ `delayed` / `stale`（落后 ≥2 个交易日）/ `failed`（本交易日窗口内的发布尝试失败）/ `unknown`。周末与假日不会把周五快照判为过期。价格覆盖暂停只发生在 GitHub job 内、没有持久记录，因此只说“尚未发布”，不臆断原因。
   - 警报：`GET /api/alerts/attention` 需登录、`private` 缓存，复用收件箱同一评分（≥45 且未处理/未暂缓）与同一 50 条窗口；徽章上限 99+，提示里给完整数。未登录不显示；读取失败显示“?”。
   - 演化监控：读取每日因子循环最近一次 `cron_runs` 与 GitHub workflow 状态，区分 `disabled`（主动关闭，不是故障）、`paused_after_failure`（熔断后暂停）、`failed`、`schedule_missed`、`awaiting_schedule`、`idle`、`not_configured`、`unknown`。待审提案数单独提示并定位 `#evolution-review`。
   - 其它路由无状态契约，不加徽章。
3. **读取成本**：一次公共请求、单条 SQL（全部 `LIMIT 1`/计数走既有索引），边缘缓存 120s + SWR；GitHub workflow 状态每实例 15 分钟最多读一次，失败同样缓存。前端合并进既有 `SystemHealthProvider`，可见页每 5 分钟一次，不为每项单独轮询，不调用 LLM。
4. **折叠**：桌面 200px ↔ 56px 轨道；偏好写 cookie，由服务端 layout 读取，首帧即正确宽度。只改变 grid 第一列，`<main>` 不重挂载，筛选、分页与滚动位置保留。轨道上图标 + 方形状态点；悬停与键盘焦点显示双语名与状态说明；仅颜色过渡，尊重 reduced-motion。

## 设计原则复核

| 原则 | 落点 |
| --- | --- |
| 状态可见 | 徽章文字（延迟/失败/已暂停/数字）+ tooltip 说明交易日与下一次发布时间，不只靠颜色 |
| 信息诚实 | 读取失败为“?”，不保留旧绿色；主动暂停不标为故障；价格暂停原因不臆测 |
| 认知负担 | 只有 3 个路由可能出现标记；无状态契约的路由不加装饰 |
| 可恢复 | 点击进入对应页面；演化待审直接定位审查区 |
| 尊重时间 | 一个聚合请求 + 一个私有计数；折叠不重置页面 |
| 设计连续 | TM tokens、mono 12px、`TmIconButton`、`TmTooltip`；新增 10 个 Lucide 图标已登记到 `/reference` |
