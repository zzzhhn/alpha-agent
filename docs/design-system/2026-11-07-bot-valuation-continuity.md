# 机器人估值连续展示与低频行情更新

## 目标与边界

用户报价过期后仍能判断最近已确认的账户表现。保留现有 TM 账户概况、布局与交易操作，只调整估值状态和数据契约；不改投资参数、BYOK、人类账户或交易门槛。

## 数据契约

- 现有 `portfolio_value`、`unrealized_pnl`、`total_return_pct` 继续表示当前可确认估值，过期/缺失仍可为 null。
- 新增只读 `last_valid_valuation`，来自当前 owner/account/reset cohort 的有效 `sim_equity_daily` 记录。仅供历史展示，不注入机器人上下文、风控或撮合。
- 快照包含净值、浮盈亏、总收益、记录时间、交易日及质量。`valued_at` 是该有效估值被记录的时间，不把它称作成交时刻或逐笔报价时刻。
- 查询仍为空时，显示“尚无完整有效估值”；不以现金、成本价、零收益或其他 cohort 的记录代替。
- 同一日更新失败，不覆盖该日已有的有效估值；更早的并发更新不能覆盖更晚记录。盘中快照仍标 `fresh`，不因收盘后保留它而改成 `session_close`；共同收盘收益统计继续排除盘中数据。

## 运行与资源预算

- 独立鉴权入口 `/api/cron/paper_bot/valuation`，Vercel cron 为 UTC `7,37 13-21 * * 1-5`。实际执行受 XNYS 日历约束：盘中及收盘后 15 分钟窗口，兼容夏令时、节假日、半日市。
- 常规交易日约 13 次盘中更新加 1 次收盘检查。仅持仓与 SPY；当前 8 只持仓约 126 次代码行情读取/交易日，不是 126 次 LLM 调用，也不是对底层供应商 HTTP 次数的承诺。
- 全局每轮最多 21 个不同代码、10 个活动机器人账户、并发 2、总时间 120 秒。共享当轮报价缓存；预算不足则整账户延期，避免故意以缺价重写它。优先较久未估值的账户，跳过正在决策的账户。
- 复用一条 `cron_runs` 状态记录和短事务 advisory lock，计划槽去重，异常后等待后续低频时段，不紧密重试。不在网络等待期间持有事务或专用连接。
- 接近现有存储预算 80% 时跳过；不扩容、不清理用户历史、不新增表。只更新持仓最新报价和每账户每天一条净值记录，不存储分钟 bar 明细。
- 页面每 5 分钟只读账本、净值曲线与统计；隐藏标签页停止，活动机器人运行沿用原轮询。读取失败保留已有账户信息。页面读取不抓行情、不调用模型、不写库。
- GitHub worker 仅增加独立 `valuation_refresh` 操作以便有界验证；普通机器人决策计划不变，两个调度入口不会因行情任务多发一次决策。

## 交互与原则复核

| 原则 | 本次落点 |
| --- | --- |
| 意图、认知负担、无需说明书 | 当前值失效时原位展示最近有效值，不新增页面或复杂切换 |
| 状态可见、不误导、可追踪 | “最近有效净值”“历史快照”与时间紧邻数值；当前现金另行标明 |
| 可恢复、尊重时间 | 一次刷新失败不清空旧值；后台低频更新且前端隐藏即暂停读取 |
| 可供性、单一主操作 | 保留立即唤起与原有刷新，不新增暗中调用 LLM 的按钮 |
| 设计服务任务 | 复用 TmPane、Metric、语义色、原字体和间距，不重做视觉身份 |

中英字符串继续使用 `sim.bot.*` 命名空间及 locale provider，时间沿用北京时间标注；深浅色语义 token、页面路径和侧栏不变。未知、有效、历史回看、读取失败分别验证。

## 验证边界

真实临时 Postgres 测试覆盖持仓行情更新、计划槽去重、失败保留有效快照、当前字段仍为空、cohort 隔离、状态行与日记录不增长；成交价格的旧价拒绝规则继续跑现有测试。发布时为周六，生产自然盘中 tick 尚不可观察；只读页面、休市退出、鉴权与部署分别验收，不以周末退出冒充盘中抓价成功。
