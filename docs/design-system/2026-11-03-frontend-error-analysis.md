# 前端设计问题复盘与复发预防

日期：2026-11-03。按用户指定的 error-analysis 工作流完成。

## 结论

主要问题不是缺少设计规则，而是把“组件已统一／代码已通过”误当成“用户能顺畅使用”，并且没有持续把用户否决的方向从当前规范中退出。改进应落在真实页面的浏览、选择、理解、恢复这条路径，而不是再增加一套风格、动效库或长篇指令。

本报告归纳八个问题族。次数只记录可证实的案例／用户反馈，不声称已统计整个旧会话；没有读取完整旧 JSONL。当前代码、已写入的页面记录和本 session 用户反馈是依据，历史截图中未重新复现的问题不冒充当前仍存在的 bug。

## 分层措施

### 已实施

1. 合并已审阅的 Alpha／Alerts 代码，保留两个功能分支的来源；唯一合并冲突是资产目录顶部的两段新增记录，两段均保留。
2. 更新主设计规范与旧动效记录，建立本复盘目录及验收入口，不添加另一套设计系统。
3. 使用上轮已有针对性测试、真实同页截图与交互检查；本轮仅做集成与正式域名检查，不重复无关后端／数据库负载测试。

### 后续页面沿用

- 从当前生产页建基线，确定任务与保留边界。
- 覆盖当前改动最相关的首／中／末页、空态、选中详情、失败恢复，按风险取舍。
- 对真实内容测滚动、裁切、焦点、参数传递与状态文案，不要求每次穷举全站。
- 用户否决的方向在原记录标明失效；不只在聊天口头接受、文档仍继续推荐。

### 暂不增加

不新增全局阻塞 hooks、全站截图矩阵或新的审美 skill。审美、语言理解与状态语义无法由静态 hook 可靠判定；现有设计系统审计继续负责客观的 token／图标／字号边界。只有同一可检测错误再次出现且成本合理时，才添加相应的轻量回归检查。
