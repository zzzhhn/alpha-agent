# 模拟仓推荐闭环重设计

日期：2026-07-28

分支：`codex/alpha-paper-recommendation-loop`

视觉锚点：`docs/designs/2026-07-28-paper-recommendation-loop-v1.png`

## 1. 结果定义

模拟仓不是独立的迷你券商，而是“今日推荐”的行动臂。用户进入 `/paper` 后，不离开页面即可完成：

1. 看见今日推荐及其最新可用收盘价和日涨跌。
2. 选择一条推荐，订单区立即继承 ticker、推荐日期和方向。
3. 提交模拟单，明确看见日频成交规则和预计金额。
4. 在持仓中看见该仓位来自今日推荐、自主交易或混合来源。
5. 在同一屏回看净值、SPY 基准、订单状态和来源覆盖。

完成标准：页面不再依赖四个孤立 tab；主流程不要求手输 ticker；价格口径不冒充实时；归因只陈述数据库能证明的来源，不伪造逐笔收益因果。

## 2. 当前地面事实

- 生产 `/paper` 返回 200，但未登录时仍展示四个 tab 和自动播放的 8 步 tour，主体大面积为空。
- `/api/paper/*` 八条路由已部署，V038 已提供 `pick_date`、`pick_ticker` 和按 ticker 的来源笔数。
- `RatingCard` 目前没有公司名、最新价格、价格日期和日涨跌，无法支撑“不猜 ticker”的上下文下单。
- 现有归因端点只能证明某 ticker 有多少跟单和自主成交，不能把混合持仓的盈亏严格拆成两类。

## 3. 信息架构

### 顶部

- 页面标题和常驻成交口径。
- 账户净值、可用现金、总收益、未实现盈亏四个紧凑指标。
- 可恢复的账户重置仍使用两步确认。

### 主工作区

- 左侧占主要宽度：今日推荐表。
- 右侧：当前所选推荐的上下文订单区。
- 点击推荐行或“跟单”仅改变当前选择，不跳页，不打开 drawer。
- 订单区只有一个填充式主操作“提交模拟单”。

### 验证区

- 左侧：持仓与来源，显示推荐、自主或混合来源。
- 右侧：净值曲线与来源统计，明确写“同期记录”，不写“导致”。
- 页面底部：最近订单，可取消挂单并查看失败原因。

### 引导

- 移除首次进入自动遮罩 tour。
- 顶部常驻三步流程“选推荐、提交模拟单、回看归因”。
- 问号按钮按需展开 guidebook，不抢占用户焦点。

## 4. 数据契约

扩展 `/api/picks/lean` 的 `LeanCard`，新增：

- `company_name`
- `company_name_zh`
- `latest_price`
- `price_date`
- `daily_change_pct`

价格来自 `daily_prices` 最新两条日线收盘价。缺任一条时涨跌为空。页面明确展示“最新可用收盘价”和日期，不使用“实时价格”。

扩展 `/api/paper/attribution` 的 ticker 行，新增：

- `latest_pick_date`
- `source_type`，枚举 `pick`、`manual`、`mixed`

`source_type` 只按已成交订单的来源笔数分类。盈亏仍是当前 ticker 的合计值。混合来源不得被硬拆成推荐和自主收益。

## 5. 交互状态

- 推荐加载成功：默认选择第一条，但不自动下单。
- 推荐加载失败：订单区进入无选择状态，账户和持仓仍可用。
- 未登录：推荐仍可见，订单区展示登录 CTA，账户相关区域显示登录后可用。
- 下单中：主按钮原位显示提交状态并禁用。
- 下单成功：订单区原位显示结果，刷新账户、订单和归因。
- 下单失败：原位显示可操作错误，不丢失选择和已填数量。
- 所选 ticker 从新推荐列表消失：回退到第一条可用推荐。

## 6. 十原则 re-check

| 原则 | 本次落点 |
|---|---|
| 意图对齐 | `PaperScreen` 首屏直接显示推荐和上下文订单，不先让用户选 tab。 |
| 认知负担 | 同一选择状态连接推荐、订单和持仓来源，移除四个页面状态。 |
| 状态可见 | `SimOrderForm` 在原位呈现提交、成功和错误；各数据区独立降级。 |
| Forgiveness | 选择可随时切换；账户重置继续使用 `TwoStepConfirm`；挂单保留取消能力。 |
| Affordance | 只有推荐行和“跟单”按钮改变选择，填充按钮只代表提交订单。 |
| 好设计会消失 | 核心路径不要求记住 ticker、tab 位置或 tour 步骤。 |
| 无说明书 | 常驻三步流程即最小 guidebook，默认不遮挡页面。 |
| 尊重时间 | 推荐、账户、订单、净值、归因并行请求；单区失败不阻塞全屏。 |
| 不撒谎 | 永久展示日频口径；价格带日期；来源统计不用因果语言。 |
| 单一主操作 | 当前选择下仅“提交模拟单”为填充式主按钮。 |
| 可追踪性 | 持仓和订单展示 `pick_date` 与来源，变化可回到真实订单记录。 |

## 7. Cross-cutting conventions audit

| 项目 | 处理 |
|---|---|
| i18n | 新文案进入 `frontend/src/lib/i18n.ts`，中英文键同步。 |
| 字体 | 数字和标签沿用 `font-tm-mono`，正文沿用平台既有字体。 |
| layout wrapper | 继续使用 `TmScreen`、`TmPane`，不另造页面壳。 |
| sidebar | 保留 DECISIONS 组和现有 `/paper` 导航，不新增平行入口。 |
| locale 数据 | 公司名按 `name_zh` 优先、英文名回退；数值使用统一格式化。 |

## 8. 非目标

- 不引入盘中价格、K 线成交或虚构的实时状态。
- 不实现期权、止损、partial fill、多账户、排行榜或社交功能。
- 不在本轮重写撮合引擎。
- 不把混合来源持仓的盈亏伪拆成“跟单收益”和“自主收益”。

## 9. 验证

1. 后端单测：两条日线正确形成最新价和日涨跌；单条日线时涨跌为空；来源分类三种状态正确。
2. OpenAPI 快照和前端生成类型同步。
3. 前端 `tsc`、Vitest、Next build 全绿。
4. `next start` 真正请求 `/paper` 和旧 `?tab=` URL，均返回 200。
5. Playwright 用模拟 API 数据截 1536×1024、1024×768、390×844 三种视口，检查主操作、价格口径、来源标签和错误状态。
6. 生产部署只在分支合并后执行；完成声明必须再核验后端 JSON content type、OpenAPI 路由数和前端 bundle。
