# Alpha Agent 全模块审计与优化记录

日期：2026-09-05。范围：Alpha Agent 独立仓库、15 个桌面工作区路由、生产 API、Neon 数据库与 GitHub Actions。

## 交付边界

本轮沿用现有 Workstation 设计系统，修复可复现故障、共享组件问题及明确的性能与权限缺陷。没有调整 BRAIN 通过门槛、推荐持有周期或交易收益口径，没有删除研究账本、模拟仓历史和 BRAIN 候选记录。

用户确认：全局策略修改、审批、迁移与管理操作只允许自己的管理员账户执行；普通账户自己的模拟仓、BRAIN 挖掘、BYOK 继续可用。部署变量 `ALPHACORE_ADMIN_USER_IDS` 是权限来源，未配置时拒绝管理操作。

## 数据库空间与查询策略

基线：281,870,336 字节，约 268.8 MiB。大表依次为慢速信号 73.1 MiB、分钟行情 54.5 MiB、快速信号 35.7 MiB、新闻 35.2 MiB、推荐快照 32.5 MiB，均含索引及 TOAST。

本轮优先减少重复索引与重复写入。分钟行情的保留窗口沿用既有 1 天策略，只修复抓取重新回填旧数据的问题。慢速信号仍为中长周期研究的重要输入，未经归档验证不能仅为省空间而一刀切删除。研究账本、BRAIN 候选和模拟仓 cohort 历史保留。

PostgreSQL 的普通 VACUUM 主要让内部页可复用，不承诺立刻缩小物理文件；VACUUM FULL 要重写表并持有强锁。本轮不执行 VACUUM FULL。参考 [PostgreSQL 官方维护说明](https://www.postgresql.org/docs/current/routine-vacuuming.html)。连接池采用小进程池，与 Neon 的服务端池配合，参考 [Neon 连接池说明](https://neon.com/docs/connect/connection-pooling)。

## 安全维护与兼容性

- Next.js 从 14.2.35 升至 15.5.25，更新异步 route params，并把文件追踪根限定为 frontend，避免误扫描用户主目录。
- NextAuth 升至 5.0.0-beta.32，pg-adapter 升至 1.11.3；修正登录对象存在性检查。依据：[Auth.js 官方公告](https://github.com/advisories/GHSA-8fpg-xm3f-6cx3)。
- Nodemailer 升至 10.0.0。项目仅在密码重置中直接使用 SMTP，未启用 NextAuth 的邮件登录 provider。覆盖 Auth.js 的可选邮件 peer 版本，保留相同 `createTransport/sendMail` 调用，使用无外部发送的 stream transport 检查兼容性。
- 更新受影响的 PostCSS、nanoid 和可兼容的传递依赖。最终以锁文件的 `npm audit` 结果为准。
- 管理员身份来自后端部署配置，客户端只负责按钮呈现。API 的 403 才是权限边界。

## 设计原则与跨页面检查

状态可见：健康指示与实际任务链一致。认知负担：固定六轴、稳定数值表、局部错误。恢复：保留上次结果并提供重试。真实性：缺测和中性区分，不伪造数据。桌面密度：窄区域不强行并列两个复杂面板。键盘：复用 TmTooltip、按钮和统一焦点。色彩：只使用 TM 语义色并有文字。国际化：新增维度中英映射、权限提示双语。流程：普通账户研究操作保留，管理操作明确只读。历史：不可变账本保持追加写入。跨模块：共享壳层和反馈统一，各模块原有任务画布保持独立。

## 后续观察

1. 真实浏览器登录后的管理员按钮和普通账户只读状态，应持续覆盖在发布验收中。
2. 历史行情中的无效价格仍保留原始证据；需要按明确股票、日期从可信源重抓，而非凭空修值。
3. 分钟行情抓取改为保留窗口后，用后续调度周期确认写入量与表大小稳定。此处不把代码修复宣称为长期稳定性已验证。
4. 本轮修复的是可用性、正确性、资源开销和交互。因子研究质量与实盘收益仍须独立的样本外研究和前瞻验证，不能用工程测试替代。
